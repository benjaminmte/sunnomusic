這套系統的依據是什麼？

這個工具不是隨意設計的分類，背後有各自獨立、但互補的研究基礎：「為什麼要先捕捉」、「為什麼要用 PARA 分類」以及「CODE 產出循環」。

1. 為什麼想法要先捕捉，而不是直接想辦法解決？

蘇聯心理學家 Bluma Zeigarnik 在 1927 年觀察到一個現象：比起已完成的事，人的大腦對「未完成、還沒處理」的事情記得更牢、也更容易反覆浮現干擾注意力——這後來被稱為「蔡加尼克效應 (Zeigarnik Effect)」。

白話講：一件事只要還「懸在那裡沒被記錄」，大腦就會不斷用背景程序提醒你，這也是為什麼待辦事項愈積愈多，人會愈來愈焦慮、愈難專注。

生產力研究者 David Allen 在《Getting Things Done》裡把這個原理應用成方法論，提出「你的大腦是拿來產生想法，不是拿來裝想法的」。把想法寫下來、移出腦袋，是唯一能真正關掉這個背景程序的方式——這就是「收集區」存在的原因：不用判斷、不用分類，先寫下來，大腦才會安靜。

2. 為什麼用 PARA，而不是傳統的「主題分類」？

PARA 方法由生產力研究者 Tiago Forte 提出（著作《Building a Second Brain》），核心主張是：傳統筆記系統習慣依「主題」分類（例如「行銷」「健康」「旅遊」），但這種分法有個根本問題——很多筆記同時屬於好幾個主題，你永遠不知道該歸在哪一類，最後乾脆不歸類，系統就開始腐爛。

PARA 的解法是換一個分類的軸線：不問「這是什麼主題」，改問「這個資訊現在對我有多少行動性 (actionability)」。這也是為什麼這個工具的五個分類，是照著「要不要做、有沒有終點、是否該封存」來分，而不是照內容主題來分。

3. CODE 思考與產出循環

C (Capture 捕捉)：先將腦海想法快速卸載至「收集區」，消除背景雜訊。
O (Organize 組織)：依據行動性分流至 PARA，而非無效的主題標籤。
D (Distill 提煉)：點擊「✏️ 筆記」提煉核心摘要（Executive Summary），形成可隨時取用的「中間封包 (Intermediate Packets)」。
E (Express 表達)：將累積的筆記匯出至 Obsidian 等工具，直接拼裝成文章、報告或專案產出。

4. 為什麼要每週回顧？

捕捉解決的是「記不住」，但沒有回顧，系統會變成另一個沒人看的垃圾場。收集區裡放超過 7 天的項目會自動提醒你，就是為了補上這一步。

簡單說

捕捉，是為了關掉大腦裡的背景雜訊；PARA 與 CODE，是為了讓你在真正需要用到某個資訊的當下，能立刻找到並轉化為產出——而不是花時間回想「這個我當初歸在哪一類」。
